## 4. Procedure for a future check

Run it on a test machine, not on the working server, and do not change the working server's
settings for this.

1. Record the hardware, operating system, driver, back-end version and the model file with its
   SHA-256 (fill in section 3).
2. Write one de-identified test prompt of a known length (count the tokens with the model's own
   tokenizer). Save it in the repository next to this file.
3. Start the back end with the 64k context. Write down the exact command and settings.
4. Run the prompt at least five times with one client. For each run record the time to first token,
   the generation speed in tokens per second, and the VRAM and RAM in use.
5. Repeat with the number of parallel clients you claim to serve (for example 2, 4, 8). Record the
   same numbers and any error.
6. Start again with the 262k context. If it fails, copy the exact error message and the memory
   figures at the moment of failure.
7. For every number say which command or tool produced it. Do not average away failed runs.
8. Fill in the conclusion: what is confirmed and what the limits of the test are. Then change the
   status in the [Lab chapter](../book/05-lab.md#current-experiments) from "author-reported" to
   "reproduced", with a date.
