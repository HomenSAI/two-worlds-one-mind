## 4. Verfahren für eine künftige Prüfung

Führen Sie sie auf einem Testrechner aus, nicht auf dem Arbeitsserver, und ändern Sie dafür nicht die
Einstellungen des Arbeitsservers.

1. Erfassen Sie Hardware, Betriebssystem, Treiber, Backend-Version und die Modelldatei mit ihrem SHA-256
   (Abschnitt 3 ausfüllen).
2. Schreiben Sie eine anonymisierte Testeingabe bekannter Länge (zählen Sie die Tokens mit dem Tokenizer des
   Modells). Speichern Sie sie im Repository neben dieser Datei.
3. Starten Sie das Backend mit 64k Kontext. Notieren Sie den genauen Befehl und die Einstellungen.
4. Führen Sie die Eingabe mindestens fünfmal mit einem Client aus. Erfassen Sie bei jedem Lauf die Zeit bis
   zum ersten Token, die Erzeugungsgeschwindigkeit in Tokens pro Sekunde sowie den belegten VRAM und RAM.
5. Wiederholen Sie mit der Zahl paralleler Clients, die Sie zu bedienen behaupten (zum Beispiel 2, 4, 8).
   Erfassen Sie dieselben Werte und jeden Fehler.
6. Beginnen Sie erneut mit 262k Kontext. Scheitert er, kopieren Sie die genaue Fehlermeldung und die
   Speicherwerte im Moment des Scheiterns.
7. Sagen Sie bei jeder Zahl, welcher Befehl oder welches Werkzeug sie erzeugt hat. Mitteln Sie gescheiterte
   Läufe nicht weg.
8. Tragen Sie die Schlussfolgerung ein: was bestätigt ist und wo die Grenzen des Tests liegen. Ändern Sie dann
   den Stand im [Kapitel Labor](../book/de/05-lab.md#aktuelle-experimente) von „vom Autor berichtet“ auf
   „reproduziert“, mit Datum.
